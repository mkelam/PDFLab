## Story

**As a** DevOps engineer,
**I want** to restart the staging backend container with updated database credentials,
**so that** the application can connect to MySQL and serve API requests.

---

## Context

The staging backend container is currently DOWN due to MySQL connection errors. Now that we have wildcard permissions (`pdflab_staging_new@'%'`), we can restart the container with updated credentials.

**Container Status**: 🔴 Exited (1) - MySQL connection refused
**Target Status**: ✅ Up and healthy - Serving requests on port 3007

---

## Acceptance Criteria

1. ✅ Backend container starts successfully
2. ✅ Container connects to MySQL without errors
3. ✅ Health endpoint returns HTTP 200
4. ✅ Container logs show "Server running on port 3006"
5. ✅ Container set to restart policy: `unless-stopped`

## Dev Notes

### Container Startup Commands

**Option A: Simple Start** (if .env already in container)
```bash
ssh root@141.136.44.168
docker start pdflab-backend-staging
docker logs -f --tail 100 pdflab-backend-staging
```

**Option B: Update Env Then Start** (recommended)
```bash
# Create updated .env with new DB_USER
cat > /tmp/updated.env <<EOF
DB_USER=pdflab_staging_new
DB_PASSWORD=StagingDB2024!UserPass
DB_HOST=mysql-staging
# ... all other vars ...
EOF

# Copy to container
docker cp /tmp/updated.env pdflab-backend-staging:/app/.env

# Start container
docker start pdflab-backend-staging
```

**Option C: Restart with Env Override** (quick test)
```bash
# Stop old container
docker stop pdflab-backend-staging
docker rm pdflab-backend-staging

# Start new container with updated env
docker run -d \
  --name pdflab-backend-staging \
  --restart unless-stopped \
  --network <network-name> \
  -p 3007:3006 \
  -e DB_USER=pdflab_staging_new \
  -e DB_PASSWORD=StagingDB2024!UserPass \
  -e DB_HOST=mysql-staging \
  ... (all other env vars) \
  pdflab-backend-staging:latest
```

### Troubleshooting

**Issue: Container exits immediately**
```bash
# Check exit code
docker inspect pdflab-backend-staging --format='{{.State.ExitCode}}'
# 1 = Application error
# 137 = Killed (OOM)
# 139 = Segmentation fault

# Check last 100 log lines
docker logs --tail 100 pdflab-backend-staging
```

**Issue: Container stuck restarting**
```bash
# Check restart count
docker inspect pdflab-backend-staging --format='{{.RestartCount}}'
# If > 5, something is broken

# Disable auto-restart to debug
docker update --restart=no pdflab-backend-staging
```

**Issue: Can't connect to MySQL**
```bash
# Test MySQL connection from backend container
docker exec -it pdflab-backend-staging sh
mysql -h mysql-staging -u pdflab_staging_new -p
# Enter password, should connect

# If fails, check network
docker network inspect <network-name>
# Verify both containers on same network
```

**Issue: Port 3007 not responding**
```bash
# Check if port is bound
docker port pdflab-backend-staging
# Expected: 3006/tcp -> 0.0.0.0:3007

# Check if port is listening on VPS
netstat -tuln | grep 3007
# Expected: tcp 0 0 0.0.0.0:3007 LISTEN

# Check firewall
ufw status | grep 3007
```
