## Story

**As a** DevOps engineer,
**I want** to locate the MySQL root password for the staging environment,
**so that** I can grant wildcard permissions to the pdflab_staging user and unblock container restart.

---

## Context

The staging backend container is down because the MySQL user `pdflab_staging` only has permissions from a specific IP address (`172.20.0.3`). When Docker containers restart, they get new IP addresses, causing "Access Denied" errors.

**Current Error**:
```
Access denied for user 'pdflab_staging'@'172.20.0.5' (using password: YES)
```

To fix this, we need to grant wildcard permissions (`'pdflab_staging'@'%'`), which requires MySQL root access.

## Dev Notes

### VPS Access
- **Host**: 141.136.44.168
- **User**: root
- **SSH**: `ssh root@141.136.44.168`

### MySQL Container Info
- **Container Name**: mysql-staging (or similar - check with `docker ps`)
- **Database**: pdflab_staging
- **User**: pdflab_staging (current, needs wildcard permissions)
- **Expected Root User**: root@'%' or root@'localhost'

### Common Password Locations
1. Environment files: `.env`, `.env.staging`, `.env.production`
2. Docker compose files: `docker-compose.yml`, `docker-compose.staging.yml`
3. Kubernetes secrets: `kubectl get secrets` (if using k8s)
4. CI/CD variables: GitHub Secrets, GitLab CI/CD variables
5. Infrastructure-as-code: Terraform variables, Ansible vaults

### If Password Not Found
**Option 1: Reset MySQL Root Password** (15 minutes)
```bash
# Stop MySQL container
docker stop mysql-staging

# Start in safe mode (skip grant tables)
docker run --rm -d --name mysql-temp \
  --volumes-from mysql-staging \
  mysql:8.0 --skip-grant-tables

# Connect without password
docker exec -it mysql-temp mysql

# Reset password
FLUSH PRIVILEGES;
ALTER USER 'root'@'%' IDENTIFIED BY 'NewSecurePassword123!';
FLUSH PRIVILEGES;
exit

# Stop temp container, restart normal container
docker stop mysql-temp
docker start mysql-staging
```

**Option 2: Create New Privileged User** (5 minutes)
If root password is irrecoverable, connect via socket and create new admin user:
```bash
# Enter container
docker exec -it mysql-staging bash

# Connect via socket (no password needed)
mysql -u root

# Create new admin user
CREATE USER 'admin_staging'@'%' IDENTIFIED BY 'SecurePassword123!';
GRANT ALL PRIVILEGES ON *.* TO 'admin_staging'@'%' WITH GRANT OPTION;
FLUSH PRIVILEGES;
```

### Security Notes
- **Never commit passwords to version control**
- Use environment variables for production passwords
- Rotate passwords quarterly (add to calendar)
- Use strong passwords (min 16 chars, mixed case, numbers, symbols)
- Consider using secrets management (HashiCorp Vault, AWS Secrets Manager)

### Testing
To verify the password works:
```bash
# Test 1: Connect as root
docker exec -it mysql-staging mysql -u root -p
# Enter password, should see: mysql>

# Test 2: Show databases
SHOW DATABASES;
# Should see: pdflab_staging

# Test 3: Verify GRANT privilege
SHOW GRANTS FOR 'root'@'%';
# Should include: GRANT ALL PRIVILEGES ON *.* WITH GRANT OPTION

# Test 4: Test granting permissions (dry run)
SHOW GRANTS FOR 'pdflab_staging'@'%';
# Will show current grants or error if user doesn't exist
```

## Risks & Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| Password not in any common location | HIGH | Use password reset procedure (Option 1) |
| Password reset breaks production | CRITICAL | This is STAGING only, not connected to production |
| Locking out all access | HIGH | Test new password before closing root session |
| Password exposed in terminal history | MEDIUM | Clear history after: `history -c` |
